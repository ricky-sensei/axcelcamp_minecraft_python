## どんなプログラムか

プレイヤーの周りに金ブロックを10個ばらまき、全部踏むまでの時間を計るミニゲーム。踏んだ金ブロックは丸石に変わり、プレイヤーが5マス上に飛び上がる。全部踏むとチャットにタイムが出る。

ゲームの動き自体は、元のファイルから変えていない。

## アレンジの詳細

### 1. 冒頭に説明（docstring）を追加

- 変更前：作者とライセンスのコメントだけ。
- 変更後：「あそびかた」「しくみ」「アレンジしてみよう」「注意」の4つを書いた。
- 「あそびかた」は子ども向けの文体、「しくみ」と「注意」は先生向けの文体のまま。

### 2. 変数名を日本語のローマ字に変更

```python
# 変更前
goldPieces = 0

# 変更後
nokori_block_kazu = 0
```

理由：英語の変数名は、子どもに意味が伝わりにくい。

### 3. 金の数を先頭の変数にまとめた

```python
# 変更前
while goldPieces < 10:

# 変更後
mokuhyou = 10

while nokori_block_kazu < mokuhyou:
```

理由：`10` がコードの途中にあり、変える場所を見つけにくい。

### 4. ばらまく範囲を先頭の変数にまとめた

```python
# 変更前
x = pos.x + randint(-10,10)
z = pos.z + randint(-10,10)

# 変更後
hani_x = 10 # xほうこうのはんい
hani_z = 10 # zほうこうのはんい

x = pos.x + randint(-1 * hani_x, hani_x)
z = pos.z + randint(-1 * hani_z, hani_z)
```

理由：3と同じ。変数を2つに分けたので、細長い範囲にもできる。

### 5. ブロックの種類を変数1つにまとめた

```python
# 変更前（3か所に直接書いてある）
if mc.getBlock(x,pos.y-1,z) != block.GOLD_BLOCK.id:
    mc.setBlock(x,pos.y-1,z,block.GOLD_BLOCK)
...
if mc.getBlock(pos.x,pos.y - 1,pos.z) == block.GOLD_BLOCK.id:

# 変更後
block_syurui = block.GOLD_BLOCK  # ブロックのしゅるいをきめるよ! GOLD_BLOCK=金ブロック

if mc.getBlock(x,pos.y-1,z) != block_syurui.id:
    mc.setBlock(x,pos.y-1,z,block_syurui)
...
if mc.getBlock(pos.x,pos.y - 1,pos.z) == block_syurui.id:
```

理由：元のコードでは、3か所をそろえて直さないとゲームが成り立たない。

### 6. 終了メッセージを日本語にした

```python
# 変更前
mc.postToChat("You took "+str(time()-startTime)+" seconds")

# 変更後
mc.postToChat(f"{mokuhyou} 個あつめるのに {round(time()-startTime, 1)} 秒かかったよ!")
```

理由：英語で読めない。秒数も小数点以下が長く出ていたので、小数第1位までにした。

### 7. エラーの判定を追加

```python
# 変更前：なし

# 変更後
import sys

# はんいのマスのかずより mokuhyou がおおきいと、ブロックをおききれない
masu_no_kazu = (hani_x * 2 + 1) * (hani_z * 2 + 1)
if mokuhyou > masu_no_kazu:
    mc.postToChat("エラーだよ!はんいのおおきさと ブロックのかずを 考えてみよう!")
    sys.exit()
```

理由：範囲を小さくすると、ブロックを置ける場所が足りなくなる。元の作りのままだと、置ききれずにプログラムが終わらなくなる。

## 授業で子どもに変えてもらう箇所

| 変えるもの | 変数 | メモ |
|---|---|---|
| あつめるブロックの数 | `mokuhyou = 10` | 増やすと難しくなる |
| ばらまく範囲 | `hani_x = 10`、`hani_z = 10` | 大きくすると探すのが大変になる |
| 置くブロックの種類 | `block_syurui = block.GOLD_BLOCK` | `GOLD_BLOCK` の部分を変える |

範囲とマスの数の関係：範囲1なら9マス、範囲2なら25マス、範囲10なら441マス。`mokuhyou` がマスの数を超えると、エラーのメッセージが出る。

## 気をつけること

- **平らな場所で実行する。** 金ブロックは実行したときの足元の高さにだけ置かれるので、でこぼこした地形では埋まったり浮いたりする。
- **全部踏むまで終わらない。**
- **`block_syurui` を地面と同じブロックにすると固まる。** スーパーフラットで `block.GRASS` を選ぶと、置く処理が終わらなくなる。対策は入れていない。

## 実行エラーへの対応（2026-10-05）

- 変更前：そのまま `from mine import *` を実行していた。
- 変更後：ファイル自身の位置から親フォルダを求め、`sys.path` に追加してから読み込む。
- 理由：`.axcelcamp` 内のファイルを直接実行しても、親フォルダの `mine.py` と `mcpi` を見つけられるようにする。
- 変更前：共通ライブラリが `collections.Iterable` を参照すると、新しい Python では `AttributeError` になる。
- 変更後：その名前がない場合に限り、`collections.abc.Iterable` を `collections.Iterable` に割り当てる。
- 理由：元の `goldcollector.py` と共通ライブラリを変更せずに対応するため。この補完は実行中の Python プロセス内だけに作用する。
- 授業では、この準備部分は子どもが変更する対象にしない。ゲームのルールや調整用の変数は変更していない。
- 検証：Python 3.13.9 で構文、親フォルダの読み込み、座標の生成、ブロック引数の文字列化を確認済み。Minecraft への接続とゲーム全体の動作は未確認。

## 日本語の文字化けへの対応（2026-10-05）

- 変更前：終了・エラーのメッセージを `mc.postToChat(...)` で UTF-8 送信していた。
- 変更後：この2か所を `nihongo_chat(...)` に変更し、追加した関数で CP932 に変換して送信する。改行を空白に置き換える処理は元の送信処理に合わせた。
- 理由：導入済みの RaspberryJamMod は受信時に文字コードを指定せず、この日本語 Windows 環境では CP932 として解釈する。実際のログでも終了メッセージの文字化けを確認した。
- 元の `goldcollector.py` と共通ライブラリは変更しない。ファイル自体は引き続き UTF-8 で保存する。
- 授業で子どもに変えてもらう箇所は従来どおり。関数内の通信処理は先生向けの準備部分とする。
- 注意：この対応は現在の環境向け。Minecraft 側を UTF-8 に設定した環境では、送信文字コードも合わせる必要がある。
